# OneSSH 设计文档

> 面向 AI Agent 的集中式 SSH 网关 —— 架构与设计思路

## 0. 文档说明

本文描述 OneSSH 的整体架构、各子系统的设计决策与理由。阅读对象是参与本项目的工程师，以及希望理解"为什么这样设计"的评审者。

一个重要的约定贯穿全文：**文中出现的前端框架、后端语言、数据库引擎均标注为"当前实现"，它们是设计在某一时刻的落地物，而不是设计本身**。每一处技术选型都会同时给出"如果替换，替代方案必须满足的能力约束"。第 2.4 节集中阐述这一原则；各子系统章节在涉及具体实现时同样遵守。

## 1. 背景与问题定义

### 1.1 Agent 直连 SSH 的根本问题

让 AI Agent 直接持有 SSH 私钥，安全问题并非无解——OpenSSH 本身提供了 `command=`、`from=`、`restrict`、`permitopen=` 等授权收窄手段，SSH CA 证书也能用有效期和 principals 限制一把钥匙的能力。

真正的问题是：**这些控制点分散在每一台目标主机上**。

- 调整一次授权需要登录所有机器改 `authorized_keys`，撤销同理；
- sshd 的日志只到会话粒度，看不出 Agent 在会话内究竟执行了什么命令、读写了哪些文件；
- Agent 需要为每台主机分别配置凭据，凭据散布在各个 Agent 的运行环境中。

### 1.2 设计目标

OneSSH 的答案是把这些控制点**收敛到网关一侧**：

1. **凭据不出网关**。私钥与密码加密存储在网关，只在建立 SSH 连接的瞬间解密使用，Agent 永远接触不到明文。
2. **权限可收敛**。每个 Agent 凭据（令牌）绑定一组可访问的主机；"执行命令"与"管理主机配置"是两个独立权限，后者默认关闭。
3. **随时可撤销**。令牌是网关侧的一条数据库记录，删除即失效，无需触碰任何目标主机。
4. **全程留痕**。每次工具调用、每次权限拒绝都写审计；命令执行另有逐次记录，含真实退出码与完整输出（保留期内）。
5. **Agent 侧零改造成本**。对 Agent 暴露的是标准 MCP（Model Context Protocol）服务，支持 OAuth 2.1 授权码流程的客户端即插即用。

### 1.3 非目标

- **不是堡垒机替代品**。Web 终端只是管理面附赠能力，审计粒度以 MCP 工具调用为主（交互式终端无法逐条审计，这是明确接受的差异）。
- **不做多租户 SaaS**。单一管理员的单网关模型，横向扩展不是第一优先级，但无状态设计为此留了余地（见 13.1）。
- **不在远端装任何常驻组件**。所有远端交互都是"按需 SSH + 探测脚本"，远端不需要 daemon、agent 或特殊账号权限。

### 1.4 七条设计基调

以下原则在所有子系统中反复出现，可作为评审新功能的检查表：

| 原则 | 含义 |
|---|---|
| 控制面收敛 | 一切授权、撤销、审计发生在网关，目标主机保持无感 |
| 权限不可放大 | 授权范围在签发时刻圈定，流经的每一层只能收窄、不能扩大 |
| 两端无常驻 | 网关与远端都不为单个会话/任务保留进程状态，状态物化到数据库或远端文件系统 |
| 降级显式可见 | 每一级降级都通过 `warning` / `engine` / `verified` 等字段告知调用方真相，绝不静默吞掉 |
| 破坏性操作先证明归属/现状 | kill 前证明进程归属、编辑前校验内容哈希、删除前检查引用 |
| 输出限额三重防线 | 大小、条数、字节三重上限，防止 Agent 上下文爆炸与网关内存爆炸 |
| 提示词与工具表严格对齐 | 说明层（instructions、描述、注解）与 `tools/list` 一一对应，绝不指向不存在的工具 |

## 2. 总体架构

### 2.1 部署形态：单进程网关

整个系统是一个**单进程、单端口**的网关。所有能力——MCP 端点、OAuth 授权服务器、管理 REST API、实时事件流、浏览器终端、静态前端资源——都从同一个进程、同一个端口（默认 8866）提供。

选择单体而非微服务拆分的理由：

- 部署物最小化：当前实现是一个静态编译的二进制（前端资源编译期内嵌），容器镜像里只有一个可执行文件，没有运行时依赖；
- 消除内部服务间鉴权：MCP 工具、Web 界面、终端天然共享同一套执行器、连接池与事件总线，不会出现"界面上杀不掉 MCP 起的任务"这类双轨状态；
- 单管理员模型的自然延伸：管理面与执行面同源，授权页可以直接复用 Web 会话。

### 2.2 客户端分类与接入通道

| 客户端 | 通道 | 鉴权 |
|---|---|---|
| AI Agent | MCP over 无状态 Streamable HTTP（`/mcp`） | OAuth 2.1 访问令牌或手工 Bearer 令牌 |
| 浏览器控制台 | REST + SSE + WebSocket（`/api/v1/*`） | 管理员会话 Cookie |

两类客户端访问的是**同一个运行时**：Agent 经 MCP 工具执行命令、传文件、起任务；管理员经 REST 在界面上做同样的事并管理配置。二者共享连接池、执行器、任务管理器与事件总线——观测与控制在同一份状态上发生。

### 2.3 分层与模块划分

内部分层自底向上，全部单向依赖、无环：

```
第 0 层  无内部依赖
  config        启动时一次性加载并校验环境变量（fail-fast）
  cryptox       AES-256-GCM 密封盒（唯一实现机密静态加密的地方）
  store         持久化层：领域数据 + 迁移 + 维护性写入原语
  events        进程内广播事件总线（SSE 的数据源）

第 1 层  基础设施
  sshpool       SSH 连接池：凭据解密、TOFU、跳板隧道、keepalive
  execx         远程命令执行引擎（脚本包装、trailer、限流、artifact）
  files         SFTP 客户端池与文件操作
  memoryx       记忆引擎（召回评分、嵌入、确定性维护）
  searchcore    与传输无关的搜索算法内核（FS 抽象）
  searchx       三级搜索引擎调度（原生 → 临时 helper → 纯 SFTP）
  imagex        图片解码与缩放

第 2 层  领域/长生命周期服务
  hostmanager   主机生命周期：校验、TOFU 重置、连接测试、错误分类
  jobs          后台任务管理器（无远端常驻）
  monitor       指标轮询 + 全站数据保留策略调度 + WAL 维护

第 3 层  协议/接入
  oauthserver   OAuth 2.1 授权服务器
  mcpserver     MCP 工具组装、鉴权、审计注入、卡片发布
  webapi        管理 REST + SSE + WebSocket 终端

装配点   cmd/onessh/main.go
  唯一知道全部组件的地方；显式构造依赖并挂路由
```

分层的判断标准是**依赖方向而非代码量**：`store` 不知道 SSH 的存在，`sshpool` 不知道 MCP 的存在，`mcpserver` 与 `webapi` 平级共享第 1、2 层。装配只发生在 `main.go`——任何一个组件都可以在测试里被独立构造（传入假的或真实的下层数据）。

### 2.4 技术选型与可替换性（重要）

本节回答"如果不用当前实现，设计还能成立吗"。答案是：能，但替代方案必须满足以下能力约束。**这些约束才是设计的一部分；具体产品只是约束的一个解。**

**服务端（当前实现：Go，静态编译、无 CGO）**

| 约束 | 理由 |
|---|---|
| 成熟的 SSH/SFTP 协议栈（客户端侧，含 ProxyJump 语义） | 连接层、执行层、文件层的全部能力建立其上 |
| 轻量并发单元（协程/线程）与取消传播（context 等价物） | 连接池 keepalive、命令超时竞速、并发采样、SSE 订阅都依赖"可取消的并发" |
| HTTP 服务能力：路由按方法+路径模式、中间件、SSE flush、WebSocket 升级 | 接入层四条通道的载体 |
| 编译期资源内嵌（或等价的"单文件分发"机制） | 前端资源与二进制合一的部署目标 |
| 可控的确定性终止与优雅关闭 | "两端无常驻"原则要求进程重启后状态收敛是设计出来的，不是碰运气 |

满足这些约束的运行时（其他编译型语言、带成熟 SSH 库的托管运行时）都可以承载同样的分层。**分层本身不依赖任何语言特性**——各模块以结构体/接口组合、构造注入，没有全局单例与隐式装配。

**数据库（当前实现：嵌入式单文件关系库，WAL 模式）**

数据模型只使用标准关系特性（详见第 17 章）。对存储引擎的硬约束：

1. **事务**：迁移的"执行成功与版本登记原子绑定"、令牌签发、级联删除、撤销授权族，都要求单事务多语句；
2. **声明式约束**：唯一键、CHECK、外键——不变量尽量在库层兜底而非仅靠应用纪律；
3. **游标分页**：审计与命令记录按单调 ID/序号翻页；
4. **全文检索能力**（或应用层等价物）：记忆召回的关键路径；当前实现用库内 FTS 虚表 + 触发器同步，替代方案需要提供等价的子串级匹配或改为应用层索引；
5. **写并发语义清晰**：当前实现利用"单写者"假设做了写串行化；换 C/S 数据库时该假设可放宽，但高频后台写（审计/指标）与业务写的事务隔离策略需重新评估。

嵌入式的选择服务于"单二进制 + 零外部依赖"的部署目标；若部署规模超出单机，数据层是第一个被替换的组件——持久化 API 已按领域方法收敛在单一接口后面，替换面是受控的。

**前端（当前实现：React SPA，编译产物内嵌进服务端二进制）**

前端的设计约束与框架无关（详见第 16 章）：同源部署、三通道通信（REST/SSE/WS）、服务端状态与 UI 状态分离、主题走设计令牌。任何 SPA 框架或 SSR 方案满足"同源 + 三通道 + 构建产物可内嵌"即可替换。

**可替换性声明**：本文其余章节描述的鉴权链、权限模型、状态机、降级策略、审计协议均与上述具体产品无关。提到当前实现仅是为了落地示例。

## 3. 身份、认证与权限模型

这是全系统最核心的一条设计主线。

### 3.1 三类主体

| 主体 | 凭据形态 | 能力 |
|---|---|---|
| 管理员 | 密码换取的签名会话 Cookie（24 小时） | 网关的全权管理面：主机/密钥/令牌 CRUD、审计查看、终端、OAuth 授权决策 |
| Agent（手工令牌） | 网关侧签发的 Bearer 令牌 | 按 `all_hosts` / `host_ids` / `manage_hosts` 访问 MCP 工具 |
| Agent（OAuth 令牌） | OAuth 2.1 授权码流程签发的访问令牌 | 同上，另绑定资源指示符与刷新族 |

管理面**刻意不做权限分级**：能登录 Web 控制台的人就是网关的管理员。主机级权限模型只存在于 Agent 一侧。理由：一个网关的管理员天然可以读数据库、改配置，在管理面内再做细粒度分级是伪安全；而 Agent 令牌是真正会被分发到不可控环境的凭据，权限收敛必须做在那里。

### 3.2 权限的五个层面（贯穿链路）

授权范围从产生到消亡经过五层，每层职责单一：

```
① 授权层（圈定）   管理员在授权页/令牌创建页勾选 all_hosts 或 host_ids 列表，
                   以及独立的 manage_hosts 位 → 快照落库
② 令牌层（固化）   OAuth 码交换与刷新轮换把同一份快照原样复制到访问令牌；
                   手工令牌以同构字段落库。轮换不改变范围
③ 请求层（物化）   Bearer 中间件查哈希 → 校验过期/资源 → 把授权主机集合物化
                   进请求上下文（Principal），随请求进入工具层
④ 工具层（强制）   每个涉主机的 handler 再校验一次目标在集合内
⑤ 观测层（归因）   审计、命令记录、事件都带令牌与主机标识，范围的使用可回溯
```

**为什么在第 ④ 层重复校验？** 请求层物化的集合是"快照"，而工具层是"使用点"。防御纵深：即使未来某条代码路径绕过中间件（比如新增的内部调用），工具层的检查仍然是最后一道闸。校验时区分两种错误语义：

- `unknown host`——库里没有这台主机（帮模型纠错：先用 `hosts_list`）；
- `host not authorized`——主机存在但不在授权集（这是越权，进审计）。

两种文案配合服务器级提示词形成闭环（见 13.4）。

### 3.3 `manage_hosts`：管理能力 ≠ 执行能力

`manage_hosts` 是独立的配置管理权限，默认关闭。它允许维护 SSH 目标（增删改查主机配置），但：

- **不扩大执行范围**：开了它，可执行的主机集合不变；新建的主机也不会自动加进该令牌的授权列表（有专门测试固化这一点）；
- **主机密码只写不读**：管理工具里密码参数只进不出，审计固定脱敏。

这条边界的哲学：权限拆分按"能力类型"而不是"资源"。能改配置的人不一定能执行命令，反之亦然。

### 3.4 撤销与生命周期

- **令牌删除即失效**：网关侧一行记录，无需触碰任何主机。删除 OAuth 访问令牌时连带撤销整个授权族（刷新令牌一并作废）。
- **主机删除反向收权**：删除主机时，凡授权列表包含该主机的受限 OAuth 授权（`all_hosts=0`），其访问令牌置过期、刷新令牌置撤销——权限边界随资源消失即时收紧，不留"幽灵授权"。
- **手工令牌可设置过期**；OAuth 访问令牌 1 小时短命，长期性由可撤销的刷新族承担。

**一句话总结这条链路：授权范围在授权时刻由管理员显式圈定，之后以不可放大的方式流经令牌签发、轮换、请求鉴权与工具校验的每一层，任何一层都只能收窄不能扩大，且全程留痕。**

## 4. 凭据与秘密的安全设计

### 4.1 威胁模型

- **数据库文件泄露**（备份失窃、目录权限错误）：密文必须无法解出明文 → 静态加密 + 单独保管的主密钥；
- **Agent 运行环境泄露**：Agent 只持有网关令牌，泄露面是一行可撤销的记录，而非每台主机的私钥；
- **令牌值落盘/入库**：任何令牌明文不允许出现在持久层；
- **传输路径**：生产环境强制 HTTPS（反代终止），只有 localhost/回环回调允许 HTTP。

### 4.2 静态加密（cryptox）

主机私钥与密码经 **AES-256-GCM** 加密存储，密钥是 32 字节主密钥（环境变量注入，64 位十六进制）。设计决策：

- **密封盒语义**：加密封装只暴露 `Seal/Open` 两个方法，nonce 随机生成并前置于密文（`nonce || ciphertext`），格式自包含，调用方不需要管理 IV；
- **极小的面**：无密钥轮换、无多密钥版本、无 AAD——单网关单密钥模型，刻意保持最小复杂度。代价是明示的：**主密钥丢失后所有 SSH 凭据不可恢复**，配置校验在启动时 fail-fast；
- 解密后的明文**立即清零**，只存在于建立 SSH 连接的调用栈生命周期内。

### 4.3 令牌哈希存储

手工令牌、OAuth 访问令牌、刷新令牌、授权码——一律只存 SHA-256 哈希。明文只在签发响应中出现一次。手工与 OAuth 令牌落在同一张表，区别仅在列值（来源、资源绑定、过期策略），因此两类令牌在请求鉴权与工具层的行为完全一致，无需两套代码路径。

前缀有语义（如手工令牌、OAuth 访问、刷新、授权族、客户端各有专属前缀），便于在日志与泄漏排查中一眼分类，同时前缀不参与哈希前的高熵要求——熵来自随机字节本体。

### 4.4 TOFU 主机指纹

首次连接记录目标主机指纹；此后每次连接校验，**指纹变更直接拒绝**，错误信息同时给出期望值与实际值。重装系统后需要管理员在控制台显式重置（清空指纹列 + 使连接池失效），下次连接重新进入 TOFU 记录。

设计取舍：拒绝而非警告。指纹变更可能是重装，也可能是中间人；让"接受新指纹"成为一个显式管理动作，把两种情况都交给人判断。

### 4.5 密码认证的边界（拒绝 MFA 二因子）

保存的主机密码只用于密码认证的第一步。SSH 服务端若返回 `PartialSuccessMethods` 非空（即"密码对了，但还需要第二因子"），认证**中止**——拒绝把保存的密码用于 OTP 等交互式挑战。交互式挑战校验"仅一个问题且字段不回显"，拒绝向回显字段发密码、拒绝多轮。理由：保存的静态密码永远不应被当作 MFA 因子使用；宁可连接失败，也不制造"密码被发往未知提示字段"的路径。

### 4.6 审计脱敏

审计记录参数时：密码固定替换为脱敏标记；文件正文与编辑内容只记长度。原则是**审计要能回答"谁在何时对哪台主机做了什么形状的操作"，但不因此成为第二份秘密存储**。

## 5. SSH 连接层（连接池）

### 5.1 职责

按主机名缓存 SSH 连接，负责：凭据解密 → TOFU 校验 → （递归建立跳板隧道）→ 握手 → 缓存 + 保活。上层（执行/文件/任务/终端/监控）一律通过 `Get(主机名)` 获取连接，不感知拨号细节。

### 5.2 关键设计

**两级锁防惊群。** 池级锁只保护连接表本身的查找（瞬时持有）；每主机一个条目锁，覆盖"检查在线 → 重建连接"的全过程。同一主机的并发请求中只有一个真正拨号，其余等待后直接复用新连接。连接失败只把条目标记离线、不删表项。

**keepalive 与失效传播。** 每条连接一个 30 秒周期的心跳请求；心跳失败时先在条目锁内确认"这还是我创建的那条连接"（防止误杀已被并发替换的新连接），再置离线并关闭。跳板断开的场景不需要显式处理：目标连接会在"下次使用或 30 秒内心跳"中自然失效并重建。

**跳板是普通连接的递归。** 目标主机配置了跳板时，取跳板连接本身就是一次普通的池查询（递归携带路径防环、限深 5 级），跳板享有独立的 keepalive 与复用，多条目标共享同一条跳板连接。环检测在配置写入时静态校验（见 5.3），运行时是兜底——两层防御。已知设计债：限深常量在两处硬编码对齐，需要靠同名常量与注释维持一致。

**超时的精细拆分。** TCP 建连与协议握手各 15 秒，但握手超时不能依赖客户端配置（那只管 TCP 层）——握手用独立的带超时上下文 + 定时器强杀阻塞中的握手调用，返回时区分"握手超时 / 上层取消 / 真实协议错误"三种情况。调用上下文更早取消时立即中断，避免失常目标长期占用连接与监控槽位。

**配置变更即时生效。** 主机管理器在更新/删除/重置指纹后主动使相关缓存失效——不仅失效该主机，还失效**所有以它为跳板的主机**。失效后下一跳立即按新配置重建，不存在"旧连接继续按旧凭据服务"的窗口。

### 5.3 主机生命周期（hostmanager）

- **输入校验前置**：跳板链在写入时静态校验（存在性、无环、限深 5 级）——把运行时防御前置为提交时拒绝；
- **错误分类体系**：`Invalid / NotFound / Conflict / Connection / Internal` 五类 + 解包函数，上层据此映射 HTTP 状态码或 MCP 错误，不解析错误字符串。库层唯一约束冲突被精确归为 Conflict（如重名主机）；
- **删除约束链**：有运行中后台任务 → 拒绝（Conflict）；被其他主机用作跳板 → 拒绝；通过后才级联撤销受限 OAuth 授权 → 删授权/会话/任务/指标/该主机记忆 → 删主机。级联在单事务内完成；
- **测试连接绕过缓存**：先失效再新建，测的是"当前配置能否连上"而非"旧连接还活着"；连上后跑一条短命令验证完整执行链路；
- **密码更新语义**：更新时省略密码字段表示保留旧密文；创建或切换认证方式时必须提供。避免"更新主机必须重输密码"的烦扰，也避免密码在表单里来回传输。

## 6. 命令执行子系统（execx）

### 6.1 核心问题：持久会话状态，但两端无常驻

Agent 期望 `cd` 之后下一条命令在新目录执行、`export` 的变量持续有效。传统做法是保持一个远端 shell 进程——但这违反"无常驻"原则，且远端进程的生死与网关耦合。

OneSSH 的解法：**状态回传而非状态驻留**。每条命令包装成自描述脚本：

```
cd <上次cwd> || cd $HOME
export <会话env，字典序>
{ <命令> }
printf trailer   ← 退出码 + 当前 $PWD，带随机 UUID 前缀
```

执行结束后网关解析 trailer 拿到退出码与新 cwd，存入数据库会话表（令牌 × 主机 × 标签维度）；下条命令注入。**远端没有任何常驻进程，每条命令独立、可审计、可重放**，trailer 的 UUID 前缀防止用户命令伪造同形输出欺骗解析。

### 6.2 输出限流与 artifact

- **头尾各半捕获**（256 KiB）：内存中的限流写入器前半存输出开头、后半滚动覆盖存结尾——既要启动上下文，也要报错结尾；
- **截断即转 artifact**：发生任何截断（字节或行数）时，完整输出落盘为 artifact 文件（UUID 命名），调用方分页读取。若已有全量捕获文件（命令记录场景）直接拼接文件而不重占内存；
- **UTF-8 安全分页**：按字节游标分页但保证不切在多字节字符中间，非法字节仅在文本渲染时替换，游标始终按原始字节推进。

### 6.3 超时与取消

- 同步命令上限 600 秒；超时用 SSH 信号（SIGKILL）终止再关会话——**只关通道不会让远端终止进程组**，这是必须用信号的原因；
- 状态区分 `timeout`（定时器到）与 `cancelled`（调用方主动取消，含 HTTP 客户端断开传播进来的取消）；
- trailer 解析失败（远端被强杀、非 POSIX shell）时退出码退化用 SSH 层错误，并标记"退出码未知"，不用数值正负去猜成败。

### 6.4 shell 注入防线

所有拼进远端脚本的变量（cwd、env 值、模式串）统一走单引号转义工具，一处实现、处处使用。

## 7. 文件子系统（SFTP）

### 7.1 客户端池

SFTP 客户端按主机缓存，但复用条件是"底层 SSH 连接对象未变"——连接重建则旧 SFTP 通道一并关闭重建；SFTP 子系统请求失败会反方向强制 SSH 连接重建。路径中的 `~` 由网关侧主动展开（SFTP 协议没有 `~` 语义）。

### 7.2 关键设计

**原子写入。** 写临时文件（随机后缀）→ 关闭 → 改权限 → rename 到目标。rename 等价 POSIX 原子替换。个别服务器不支持覆盖式 rename，降级为"删目标再 rename"，**降级显式可见**：结果带 `non_atomic=true` 与 warning，调用方知道存在短暂的目标缺失窗口。

**`expected_sha256` 乐观锁。** 编辑前比对当前内容哈希，不匹配即报冲突并要求重读。这是无远端锁条件下"读-改-写"的 CAS——防止 Agent 基于过期内容覆盖并发修改。多条编辑顺序应用，任一条的旧文本不唯一匹配即整体失败（防止误替换多处），成功后返回 unified diff 供自查。

**跨主机传输不在网关落盘。** 双 SFTP 通道流式直传（边拷边算哈希），目标侧走临时文件 + rename。校验用**目标机自己的 `sha256sum`**（而不是传回来再算）——信任远端工具的一次执行，比传回全部数据便宜得多；目标机缺工具时降级为"只报源侧哈希 + 未验证标记"，交回调用方判断。

**安全阀。** 读上限 4 MiB（超限拒绝）、目录列表超 500 项报错（强迫缩小范围）、前 8 KiB 探测 NUL 判二进制并拒绝（引导走图片工具或下载）。

## 8. 后台任务子系统（jobs）

### 8.1 无远端常驻的任务模型

后台任务（`job_start`）在远端以 `setsid nohup` 脱离会话启动，**任务状态完全物化在远端文件系统**：工作目录 `~/.onessh/jobs/<任务ID>/`，输出写 `out.log`，退出码写 `exit` 文件。网关对任务的一切操作（查状态、读日志、终止）都是"按需 SSH 上来读文件 + 看进程"。

因此：网关重启、断连都不影响任务；没有心跳协议；没有远端 daemon；连"网关死了任务怎么办"都不需要回答——任务本来就不依赖网关活着。

### 8.2 归属双证：宁可记 lost，绝不误杀

`kill` 一个 PID 前必须**证明这个进程是自己的**（防 PID 复用误伤无辜进程）：

1. **argv 证据**：`ps` / `/proc/PID/cmdline` 中匹配任务专属 marker；
2. **进程组证据**：setsid leader 退出后，遍历 `/proc` 找 PGID 等于该 PID 的存活成员，核验其环境变量中的任务 marker。

两证皆不成立 → 记 `lost`（诚实承认"不知道这进程怎么了"），**绝不向无法证明归属的 PID 发信号**。kill 对 setsid 任务用负 PID（整个进程组）。

### 8.3 与命令记录的联动

任务启动在同一事务内落任务行 + 回填命令记录关联（避免只出现其中一边的半状态）。任务终态映射到命令记录状态（退出 0 → 成功、非 0 → 失败、被杀 → 取消、失联 → lost），完成落库带 `WHERE status='running'` 守卫，只有第一个刷新者触发完成事件——并发刷新不会重复广播。

网关重启时：无任务关联的 running 命令直接标 lost（同步命令无法确认结果）；**有任务关联的不动**——远端进程可能还在跑，留给下次状态刷新收敛。落库失败时（远端已启动、本地写库失败）主动带身份核验地清理已启动任务，避免产出"无人可见、无法终止"的孤儿任务。

## 9. 搜索子系统（grep / find）

### 9.1 三级引擎，一个抽象

搜索能力按性能优先级分三级，但对调用方返回**同一结构**（带 `engine` 字段与降级 warning）：

```
① 远端原生 rg / fd        性能最好，流式消费、边读边限流
② 远端临时静态 helper      目标无 rg/fd 且平台匹配时，SFTP 上传一个随机命名的
                           静态二进制到 /tmp，stdin/stdin JSON 协议交互
③ 纯 SFTP 遍历            万能兜底，走与 ② 完全相同的算法内核
```

**统一内核是关键设计**：搜索算法（glob 编译、忽略文件语义、遍历防护、二进制/大文件跳过）实现于与传输无关的内核包，通过文件系统抽象接口（取当前目录/属性/列目录/打开文件）同时服务三种引擎——helper 进程内直接调用同一实现，纯 SFTP 路径用远端 FS 适配同一接口。降级不改变语义，只改变性能。

### 9.2 helper 的生命周期纪律

- 平台探测结果按主机缓存（linux/amd64、arm64 才启用）；
- 上传用独占创建防碰撞、权限 0700、协议带版本握手；
- 运行结束删除远端二进制（**跨取消上下文**——调用方取消不跳过清理），helper 自身启动即自删除，顺带清扫 /tmp 下超过 1 小时的陈旧残留；
- 任何阶段失败按连接缓存"helper 不可用"，**静默**落入 SFTP 降级（对 Agent 只表现为 warning 文本，不是错误）。

### 9.3 降级与失败的区分

- 原生工具退出码 127（未安装）→ 触发降级链；**其他非零退出码是真实错误，直接报错不降级**——降级只救"能力缺失"，不掩盖"搜索本身失败"；
- 参数含 NUL、正则无效 → 入口拒绝（不给远端制造意外）。

### 9.4 遍历防护

忽略文件（`.gitignore` 语义：层级继承合并、`!` 反选、目录锚定）之外：跳过符号链接（防环）、跳过 VCS 元数据目录、遍历上限 10 万项 / 深度 128（超限标记截断）、单文件先看大小再看前 8 KiB 是否二进制、单行超限按截断处理。搜索总超时 30 秒、输出 256 KiB。

## 10. 记忆子系统

### 10.1 Bank 模型

记忆按 `host_id` 分 bank：每台主机一个独立 bank + 一个全局 bank。召回指定主机时合并"该主机 bank ∪ 全局 bank"。主机改名记忆不丢；删除主机时其记忆级联清理。

分 bank 的理由：不同主机的运维事实（路径、端口、服务名）天然不通用，混在一个池里召回会互相污染；全局 bank 留给跨主机的通用约定。

### 10.2 混合召回评分

```
score = (0.5×语义相似度 + 0.3×全文相关度 + 0.2×重要度)
        × (0.7 + 0.3×时近度)          ← 72 小时半衰期
        × 真实性权重                    ← stated 1.0 / inferred 0.7 / tool 0.5 / unknown 0.8
```

- **全文索引用 trigram 分词**：子串级匹配，适合主机名、路径这类短词（这是第 17 章存储约束中 FTS 能力的来源）；bm25 分数 min-max 归一化后与重要度同一量纲融合；
- **语义向量是可选增强而非依赖**：配置了 OpenAI 兼容 embedding 端点才启用；向量存行内二进制，召回时全量取回内存算余弦（无向量索引的务实选择——bank 分片天然限制了单池规模）。写入或查询失败只记日志、降级纯全文，**绝不中断 Agent 调用**；
- **真实性分层**是抑制幻觉自我强化的手段："用户明确说的"天然排在"Agent 自己推断的"之上——Agent 写入自己推断的结论时被要求标注 veracity，召回时降权。

### 10.3 确定性维护（memory_sleep）

维护不调用 LLM，只执行三个可解释、可复现的 SQL 步骤：完全内容去重（保留重要度最高者，召回计数求和转移）→ 30 天未使用的重要度衰减 ×0.9（下限 0.05）→ 删除 90 天前、从未召回、重要度 ≤0.1 的记忆。**刻意不做成"智能整理"**——记忆库的修剪规则必须可审计、可预测，Agent 才敢依赖它。

记忆写入按 (bank, 内容) 精确查重，命中即去重升级（重要度取 max、刷新时间），不产生重复行。

## 11. 监控子系统

- **采集**：一条命令同时读 `/proc/stat`、`/proc/meminfo`、`/proc/loadavg` 与 `df -P -k`（POSIX 格式防换列，分隔标记防粘连）。CPU 利用率必须**两采样点差分**（单次 /proc/stat 是开机累计值）：轮询模式用网关内存中的上次快照；手动刷新则在一条命令里 `cat → sleep 1 → cat` 自采样。无 /proc 的环境退化为 `uptime` 至少给出负载；
- **调度**：轮询间隔可配（默认 60 秒，0 关闭），单飞互斥防并发重入（慢采样不叠加），worker 池最多 5 台并发，单主机失败不影响其他主机；
- **保留策略**：指标 7 天。监控管理器还承担**全站清理调度**（每小时：指标、artifact、命令输出过期，见 12.4）与存储层 WAL 检查点（每 10 分钟，busy 则下次重试）——清理与轮询互相独立，关轮询不清数据保留策略。

## 12. 观测子系统（审计 + 命令记录 + 事件流）

### 12.1 三个层次，三种保证

| 层 | 保证 | 存储 |
|---|---|---|
| 审计（Audit） | 每次工具调用必记、不丢 | 数据库，随库保留 |
| 命令记录（CommandRun） | 每次命令执行的完整生命周期 + 输出（7 天） | 数据库 + 0600 文件 |
| 事件流（SSE） | 尽力而为的实时推送 | 内存，可丢帧 |

"活动流可丢、审计不可丢"——事件总线用非阻塞投递（缓冲满即丢帧），慢的 SSE 消费者绝不拖住命令执行路径；而审计走数据库串行写，属于不可丢的通路。

### 12.2 审计的统一注入

审计不在每个工具处理器里手写，而是在**工具注册处统一包装**：调用前后计时、成败判定、参数脱敏序列化（密码→脱敏标记、正文→长度）、从入参反射提取主机、从上下文取令牌身份、写审计行、发事件。业务代码零感知，横切关注点一处收口——新增工具自动获得审计与活动事件。

### 12.3 命令记录状态机

```
running → succeeded | failed | timeout | cancelled | lost
```

- 判定不猜：退出码已知（含 0）按码定成败；超时定时器到是 `timeout`；调用方取消是 `cancelled`；网关在完成前重启是 `lost`（显式写明原因）；
- **快照双写**：令牌与主机同时记录 ID 与名称——防删除后 ID 复用导致历史归属漂移；列表过滤时若同 ID 令牌仍存在，还要求名称匹配；
- stdout / stderr **分文件存储**（0600），字节游标分段读取（每页上限 256 KiB），UTF-8 安全切页——详情页永不把大输出整段装进内存；
- 完成落库带 `WHERE status='running'` 守卫（幂等，防并发二次完成）。

### 12.4 输出生命周期三段式

命令输出 7 天过期，清理分三步，每步可独立失败重试：

1. **过期标记**（数据库）：置过期位、清空预览；
2. **白名单删除**（文件）：只删数据库明确判定可删的记录对应的文件——**用白名单而非"扫目录删旧文件"**，因为文件创建与数据库行落库之间有时间窗口，按文件时间扫描会误删新命令的输出；
3. **收敛标记**：删除成功后置已清理位，避免每小时把全部历史 ID 重新装载。

命令的命令文本、状态、退出码、耗时在输出过期后**仍保留在数据库**——留痕不过期，只有体积大的输出过期。

## 13. MCP 接入层

### 13.1 无状态 Streamable HTTP

MCP 端点不维护会话：每个 HTTP 请求独立鉴权，不依赖会话 ID。理由：

- 身份本来就应逐请求判定——令牌可以随时在 Web 界面撤销，无状态让撤销语义即时生效，不需要"踢会话"；
- 天然适配无粘性的水平扩展（未来多实例部署不需要会话亲和）。

配套决策：**传播请求取消**——HTTP 客户端断开时取消正在执行的工具调用，跑远程命令的网关尤其需要（客户端放弃等待时远端及时止损）。

### 13.2 鉴权链与 OAuth 发现

未携带凭据的请求得到 401 + RFC 9728 的 `WWW-Authenticate: resource_metadata` 挑战——支持 OAuth 的 MCP 客户端据此自动发现授权服务器并走完整个流程，**用户零配置接入**。手工 Bearer 令牌与 OAuth 访问令牌在中间件处统一收束（同表同哈希），之后 MCP 协议层完全不感知鉴权。

### 13.3 工具组与暴露面裁剪

工具按组登记（九组三十二个工具），组的定义是三个决策的共同依据：注册哪些工具、提示词提哪些工具、卡片发布哪些工具。`ONESSH_DISABLED_TOOLS` 按组关闭——**只有按组裁剪，提示词的整段说明才能跟着工具一起消失**。未知的组名启动即报错：拼错一个名字意味着运维以为已关闭的工具仍暴露在工具列表里，这是安全事故不是可用性问题。

关闭工具组只裁剪 MCP 暴露面：对应的运行时管理器仍然构建（Web 界面的 REST 依赖它们），Web 界面的数据查看与清理也不受影响。

### 13.4 给 Agent 的说明层

工具选得对不对，取决于服务器把话说清楚了没有。说明分三层，全部与 `tools/list` 严格对齐：

1. **服务器级 instructions**：整体工作协议——主机名从 `hosts_list` 取、优先用专用工具而非拿 exec 拼命令、长任务走后台、截断输出走分页读取、破坏性操作先确认现状、记忆红线（禁存秘密）。按工具组拼装，禁用的组整段消失；
2. **工具 description / title**：适用场景、与相邻工具的取舍、默认值与硬上限、失败时怎么办；
3. **参数 description + annotations**：每个入参有说明，每个工具标注只读/破坏性/幂等/开放世界提示，客户端据此决定是否需要用户确认。

说明层有**契约测试固化**：新增工具若缺标题、描述过短、没有注解或有参数没写说明，测试直接失败。质量约束变成结构约束，而非团队纪律。

### 13.5 MCP Apps 交互卡片

为每个工具发布一张标准协议的 HTML 交互卡片（宿主在沙箱 iframe 渲染，代替一大段 JSON）。设计要点：

- **完全自包含**：样式脚本全部内联（编译期内嵌资产 + 占位符拼装），CSP 声明零外部依赖，不申请独立沙箱源——风险面收敛到"渲染工具返回的数据"；
- **内容哈希做 URI 版本**：卡片内容变则 URI 变，宿主缓存自然失效，无需人工版本管理。附带旧版字段别名走 URI 模板发布（能读到但不进资源清单，标准客户端看到的仍是干净列表）；
- **回调白名单**：卡片内只允许只读导航类回调（翻页、进目录、刷新、复制）——**写操作一律留给模型**，用户在卡片上点按钮不会在远端产生副作用；
- **运行时契约**：postMessage 只信宿主帧与 JSON-RPC 帧、待回调表无原型防污染、握手失败降级静态渲染、回调超时按服务端真实执行边界定值（180 秒，因为现场采样与逐台刷新可能远超 20 秒）；
- 卡片可整体关闭（配置开关），被禁用工具组的卡片不再发布——**给调用不到的工具发卡片只会误导宿主**。

## 14. OAuth 2.1 授权服务器

### 14.1 模型选择

内置授权服务器与 MCP 资源服务器同进程同源。客户端形态假定为**公共客户端**（MCP 客户端的现实：没有安全的客户端密钥存储），因此安全完全压在 PKCE 上：授权码挑战强制 S256（plain 拒绝）、43 字符 verifier、授权码常量时间比较。

### 14.2 关键决策

**资源指示符强绑定（RFC 8707）**。授权请求与令牌请求的 `resource` 必须精确等于本网关 MCP 端点，否则 `invalid_target`——访问令牌钉死在本资源，防跨资源重放。对外地址在构造时校验归一（一次），未配置时按请求推导。

**动态注册开放、授权收紧。** 注册端点无需认证（符合 MCP 生态预期），但注册只拿到 client_id；真正的令牌必须经管理员在授权页显式批准。注册输入有硬边界（body 上限、回调数量 1–10、必须 HTTPS——localhost 例外）。

**授权决策绑定原始请求。** 授权页的服务端在决策时**重新解析原始查询串**（客户端 ID、回调、PKCE、resource 均以原始请求为准），页面上只呈现和提交主机选择——决策不可被页层参数篡改劫持。授权页复用 Web 管理员会话（同源的优势），授权码只存哈希，5 分钟单次有效。

**授权族（grant family）重放检测。** 刷新令牌每次使用即轮换，旧值打已用标记。检测到已用刷新令牌或授权码重放，**单事务撤销整个授权族**（该族全部访问令牌过期、刷新令牌撤销）；并发竞争用条件更新 + 受影响行数检查兜底（CAS 语义）。

**错误分级。** 协议级拒绝（码无效/已用/过期/撤销）返回 400 标准错误码不带内部细节；其他错误返回 500 让客户端退避重试，而不是把瞬时故障当成凭据永久失效。

### 14.3 令牌参数

访问令牌 1 小时；刷新令牌 30 天、每次使用轮换；授权码 5 分钟单次。刷新轮换按快照**原样复制**主机授权——轮换不改变范围（与权限不可放大原则一致：想扩范围必须重新走授权页）。

## 15. Web 管理面（REST + SSE + WebSocket）

### 15.1 与 MCP 共享运行时

管理 API 的结构体直接复用 MCP 服务层构造的执行器、文件、任务、监控管理器实例——**同一个连接池、同一套审计管道**。界面上的操作与 Agent 的调用产生同构的记录与事件。

### 15.2 三通道分工

| 通道 | 用途 | 选择理由 |
|---|---|---|
| REST | 全部 CRUD 与查询、命令输出分页拉取 | 请求-响应天然契合管理操作；大输出按字节偏移分页轮询模拟"准流式" |
| SSE | 单向实时事件广播（活动页事件流） | 浏览器原生断线重连，单向推送够用且最简单 |
| WebSocket | 唯一的交互式 PTY（终端） | 唯一需要双向低延迟字节流的场景才用 WS |

轮询按语义分级：任务表 4 秒、审计 4 秒、运行中的命令详情/日志 2 秒，**完成后自动停**——轮询只在有"进行中"状态时存在。

### 15.3 会话与安全响应头

登录换取 24 小时签名 Cookie（HttpOnly、SameSite=Strict、HTTPS 条件下 Secure），管理 API 整棵子树统一在鉴权中间件之后。所有 Web 响应带 `frame-ancestors 'none'` 与 `X-Frame-Options: DENY`——防控制台被第三方页面套壳钓鱼（含登录页与 OAuth 同意页）。

### 15.4 浏览器终端

WebSocket 升级后申请 PTY（xterm-256color），双循环转发：下行二进制帧（输出），上行 JSON（输入与窗口尺寸）。**终端不走审计管道**——交互式会话无法逐条审计，这是与 MCP exec 的明确差异，也是"终端是附赠能力"定位的体现。

### 15.5 体积边界

所有入口都有显式上限：登录/注册 body、上传下载 100 MiB、审计筛选项数（防超长 SQL）、指标时间窗——每个边界对应一类滥用场景。

## 16. 前端设计

> 当前实现：React SPA，编译产物内嵌进服务端二进制，与 API 同源同端口。本节描述的原则与框架无关——替代实现需满足：同源部署、三通道通信、构建产物可被服务端分发。

### 16.1 架构分层

```
入口（Provider 栈 + 路由表 + 全局鉴权守卫）
  ↓
页面层（13 个页面，自持 UI 状态，数据全部下沉 hooks）
  ↓
业务组件层（跨页复用：命令详情、可复制块、主机连接）
  ↓
基础组件层（自建设计系统：无头原语 + 变体 + 令牌）
  ↓
数据层（统一 API 客户端 + 集中式查询键工厂 + 两个长连接 hook）
  ↓
工具层（类名合并、格式化、审计摘要、主题 Context）
```

### 16.2 状态管理哲学

**没有全局状态库。服务端状态归数据请求层，本地 UI 状态归组件**——管理控制台的本质是"服务器状态的投影"，全局状态库只会制造两份需要同步的真相。配套的全局默认值体现同一判断：数据标记 15 秒新鲜、切窗口不重拉（管理台不希望切个窗口就闪骨架屏）。

- 列表页开"保留旧数据"模式：改筛选/翻页时旧数据原地渐隐，不塌成骨架屏丢失阅读位置；
- 变更统一"失效缓存 + 提示"模式；**批量操作顺序执行而非并发**——破坏性写不给网关/远端制造并发尖峰，失败列表与执行顺序一致，页面保留失败项供重试；
- 会话级偏好（侧栏折叠、主题）直接本地存储，不进服务端。

### 16.3 鉴权的前端策略

不维护路由守卫白名单：**任何请求返回 401 都广播全局事件**，守卫组件监听后带着当前地址（含查询串——OAuth 场景需要）跳登录；登录成功后清空查询缓存防止上一身份数据闪现。鉴权规则单点收口在 API 客户端，新增页面零成本获得鉴权。

### 16.4 组件体系与主题

- 自建薄壳组件库（无头可访问性原语 + 变体系统 + 令牌），每个组件针对本项目场景写取舍注释，不做通用库的重量级抽象；
- **主题三层**：首帧防闪脚本（渲染前读偏好加类）→ 三态主题 Provider（浅/深/跟随系统，监听系统偏好实时切换）→ 设计令牌层（组件只消费语义令牌，切主题=切类名，组件代码不知道主题存在）。终端区恒为深底（终端惯例）：局部套深色令牌类实现，而非硬编码颜色；
- 设计令牌三层结构：语义色（背景/表面/边框/文本）→ 品牌与状态色 → 专用令牌（图表四色、两档阴影）。圆角刻意只有两档，"不引入第三种"。

### 16.5 终端接入

WASM 终端内核以模块级单例 Promise 缓存（失败清缓存允许重试——**永久缓存失败的 Promise 会封死重试**）。健壮性设计值得单列：15 秒握手看门狗（目标不可达时后端挂在拨号，WS 既不 open 也不 close，没有看门狗状态机永远停在"连接中"）；每次连接递增令牌，异步回调先验令牌再改状态（防旧连接的关闭事件覆盖新连接状态）；重连前摘掉旧连接全部回调。字体先行：连接前确认等宽字体就绪——Canvas 不会在字体晚到后重绘，fallback 字体画进单元格会造成粗体字符重叠。

## 17. 数据模型与存储设计

> 当前实现：嵌入式单文件关系数据库（WAL、外键开启、写事务前取写锁避免快照升级冲突）。数据模型只用标准关系特性；存储引擎的可替换约束见 2.4。

### 17.1 实体总览

| 实体 | 职责 | 关键设计 |
|---|---|---|
| Host | SSH 目标定义 | 名称网关内唯一（工具引用键）；认证方式二选一；凭据密文不入 API（安全投影）；TOFU 指纹可空；跳板引用；标签 |
| Key | 托管私钥 | 私钥密文存储、序列化排除；删除前检查主机引用数并给出友好错误 |
| Token | Agent 凭据 | 只存哈希；来源（手工/OAuth）；权限位；资源绑定（手工令牌豁免）；过期与最近使用 |
| Token↔Host | 授权关系 | 多对多表；`all_hosts` 时省略行 |
| Session | 命令会话状态 | 令牌×主机×标签维度 UPSERT；查不到返回默认值（首用即建） |
| Job | 后台任务 | PID、状态机（running/exited/lost/killed）、日志体积；与命令记录一对一 |
| Audit | 工具调用审计 | 令牌名称快照；参数脱敏 JSON；关联命令记录 ID 列表 |
| CommandRun | 命令执行记录 | 令牌/主机 ID+名称双快照；状态机；输出三态（可用/过期/已清理） |
| Metric | 监控快照 | 主机+时间戳复合主键，同键覆盖写（轮询天然幂等） |
| Memory | Agent 记忆 | bank 归属（空=全局）；重要度/真实性/召回计数；可选向量与模型名（换模型旧向量自然出局） |
| OAuth 族 | 客户端/授权码/授权族/刷新令牌 | 全部哈希存储；授权码带墓碑（已用标记+族 ID）；刷新令牌带主机授权快照 |

### 17.2 不变量与约束策略

- **库层兜底**：名称唯一、状态机 CHECK、外键——能声明的不靠应用纪律；
- **应用层哨兵错误**：删除主机遇运行中任务/被用作跳板，返回可分类的冲突错误（库层外键给不出"为什么"）；密钥被引用同理；
- **快照原则**：审计与命令记录记录"当时的名称"，列表过滤时以名称辅助校验——历史数据的归属不随后来的删除/改名/ID 复用漂移；
- **审计/命令记录/任务相关写**在事务内原子完成（任务行+命令记录回填、授权族撤销、令牌签发），不留半状态。

### 17.3 迁移机制

- 迁移 SQL 编译期内嵌（部署不依赖外部文件）；
- **每个迁移单独一个事务**：执行 SQL 与登记版本号原子绑定——失败回滚且不登记，"跳过"与"部分应用"都不存在；
- 对历史性的加列迁移先探测列是否存在再执行（兼容"进程在 ALTER 后崩溃、登记前"的半迁移窗口）；
- 迁移列表显式登记在代码中，新增 = 加文件 + 加一行。

### 17.4 存储运维

- 打开库即设置：忙等待超时、外键开启、WAL 模式、写事务立即取写锁（避免读快照升级时的库级忙错误）；
- 高频后台写（审计/指标/清理）在进程内串行化，与业务写事务错峰；
- WAL 定期检查点（截断式，busy 重试）防 WAL 无限增长；
- 健康检查走一次数据库 ping，供 `/healthz` 返回 503——存活探针测的是"还能服务"而不只是"进程还在"。

## 18. 配置、生命周期与横切关注点

### 18.1 配置

启动时一次性从环境变量加载（可选加载启动目录 `.env`，真实环境变量优先、解析失败只告警不阻断），**fail-fast**：安全关键项（主密钥格式、管理员密码非空）不合法直接拒绝启动并给出修复提示；枚举值白名单校验（拼错即拒绝，不落默认分支）；配置是不可变值对象，注入各组件，运行期无热更新。

### 18.2 组件生命周期与重启收敛

进程重启后的状态修正是一组显式设计：

| 遗留状态 | 收敛动作 |
|---|---|
| 无任务关联的 running 命令 | 启动时标 lost + 原因 |
| 有任务关联的 running 命令 | 保留，由下次任务状态刷新收敛（远端可能还在跑） |
| SSH 连接池 | 空池重建，TOFU 指纹已有则照常校验 |
| 过期数据 | 清理调度独立于轮询，照常执行 |

### 18.3 错误处理体系

- 领域层错误**分类不解析**：五类语义（非法/不存在/冲突/连接失败/内部）+ 解包函数，接入层据此映射 HTTP 状态码与 MCP 错误；
- 协议错误与内部错误严格分流（OAuth 层尤其明显：前者带标准错误码，后者让客户端重试）；
- 取消场景的最终落库用独立于取消的上下文——**取消也要能写下终态**，否则状态机卡在 running。

## 19. 部署与交付设计

- **交付物 = 一个静态二进制**：前端构建产物编译期内嵌，运行时零外部文件、零运行时依赖（当前实现 CGO-free，覆盖主流平台与双架构）；
- 容器镜像只装二进制；数据目录挂卷（数据库、命令输出、artifact——命令输出可能含敏感数据，整个数据目录按密钥级保护）；
- 容器三阶段构建：前端构建 → 服务端构建（拷入前端产物）→ 最小运行时镜像；
- `/healthz` 探数据库存活；版本号编入二进制；
- 生产部署要求：HTTPS 反代终止、显式配置对外地址（OAuth 回调与资源指示符、图标发布都依赖它）、主密钥持久化保管。

## 20. 测试与质量策略

| 层次 | 内容 |
|---|---|
| 单元测试 | 各包独立可测（依赖注入的直接收益），含边界与失败路径 |
| 契约测试 | **工具目录契约**：新增工具缺标题/描述/注解/参数说明即失败——说明层质量结构化；**资产拼接契约**：卡片资产含非法序列即启动失败 |
| 集成测试 | 执行器、任务、文件、搜索对真实 SSH 目标的行为 |
| 卡片运行时测试 | 零依赖 Node 测试真实执行卡片运行时：报文形状、只读回调白名单（破坏性工具一律不能由卡片发起）、成功/错误态渲染 |
| 卡片预览画廊 | 浏览器直接逐张验收（浅/深/错误/窄屏），不依赖服务端 |
| E2E | 容器编排多台目标主机（含无搜索工具、/tmp noexec 的特制主机），覆盖降级链、权限、审计脱敏、终端 |

测试设计的原则：**每条降级路径与每条权限边界都有对应测试**（如"manage_hosts 不扩大执行范围"、"helper 在 noexec 主机降级 SFTP"、"刷新令牌重放撤销全族"）。

## 21. 设计原则总纲

1. 控制点收敛到网关：授权、撤销、审计、密钥——Agent 只拿一个可撤销的令牌。
2. 权限不可放大：范围在授权时刻圈定，每一层只能收窄；管理能力与执行能力正交。
3. 两端无常驻：会话状态物化在数据库，任务状态物化在远端文件系统，重启收敛是显式设计。
4. 秘密的最小暴露面：密文存储、哈希存储、明文只在用点瞬时存在、审计脱敏。
5. 破坏性动作先证明：PID 归属双证、内容哈希乐观锁、删除引用检查、白名单式文件清理。
6. 降级显式可见：每一级降级把真相（engine/warning/verified/non_atomic）交回调用方。
7. 说明层与能力面对齐：提示词、描述、注解、卡片与工具注册表同源派生，裁剪联动。
8. 限流三重防线：大小、条数、字节——保护 Agent 上下文与网关内存。
9. 横切关注点一处收口：审计注入在注册处、加密在密封盒、错误分类在领域层。
10. 部署物最小化：单进程单端口单文件，技术栈的每一层都标注可替换的能力约束，设计不与实现绑死。
